# 剧情树与存档

开始界面的两处“继续旧存档”均打开剧情树。页面只显示已走过的剧情段落、小游戏与结局分支，不显示未来章节和锁定占位。一周目完成前隐藏“非一周目”入口；完成后或已有非一周目进度时，可以切换两棵树。浏览和切换不更改当前进度。

## 节点与解锁

- 一周目：序章 → 四幕各自的入场对白、小游戏与剧本对白 → 第四幕结局演出并返回标题。
- 非一周目：四幕各自的入场对白、小游戏与剧本对白 → 最后的存档 → NE、TE、BE 三个独立结局分支。每条分支播放三段剧本并进入对应结尾字幕，然后返回标题。
- 每条主剧情对白仍分别记录准确位置。页面把同一剧本段落的对白合并为一个节点，用一句简短标题说明，不展示对白正文、行号和解锁统计。该段包含上次位置时恢复上次那一行，否则恢复该段已到达的最后一行。小游戏与结局字幕保留独立节点。
- 两棵树独立记录节点；开始非一周目不会自动解锁其后面的章节。未经过的结局保持锁定。
- UI 隐藏未解锁节点，`GameManager.restoreStoryNode` 仍校验树、节点定义和存档位置，拒绝无记录或错配的节点。

## 回访和恢复

`storyTrees[1|2]` 保存节点快照和该树的 `lastNodeId`，沿用 `zlyc_save_v1` 存储键。快照包含周目、章节、场景、对白位置、当时的剧情标记和小游戏存档，不包含剧情树自身。

回访节点保留所有已经解锁的节点、全局结局记录、当前音量设置及一周目已完成状态；剧情标记及小游戏进度则恢复到那个节点，避免后续选择污染早期剧情。再次走到同一节点时更新其快照。游戏进行中会更新当前小游戏节点的检查点。对白节点记录进入该行时的状态，所以回访选择对白可以重新作答。

第一幕保留攀山进度，第二幕从本局重新挑战，第三幕保留完整跑酷进度并等待确认恢复，第四幕保留细化的检查点存档。新游戏或清除本地存档清空两棵树，五项小游戏成就独立保留。

## 旧存档

首次加载旧存档，保留当前节点的准确对白位置、标记和小游戏存档。根据原有顺序重建已走过的必经节点，未来节点继续锁定；非一周目旧存档同时重建已完成的一周目树。旧存档未保存早期节点的历史状态，回访这些重建节点会从对应段落重新开始；未记录的结局不会被开放。

树的节点直接来自 `public/data/scenes.json` 和 `public/data/story.json`。对白节点 ID 使用场景、文本区段键和行号；有现存存档时请避免随意删除或重排行，否则对应节点无法再与原位置匹配。

`tests/story-tree.test.js` 覆盖节点权限、周目隔离、对白与标记恢复、小游戏检查点、结局分支、旧存档迁移和清除行为。

第三幕接入《最后一班车》：一周目错过列车后进入 `p1_07`，非一周目成功进入 `p2_07`，失败后继续进入新增的 `p2_station_missed`，两条结果在 `p2_08` 汇合。只解锁已走过的结果。旧玩法检查点回到青年剧情入口，上一版纯剧情对白保留位置；新增跑酷节点需实际进入才解锁。详见 `STATION_RUNNER.md`。
