# 剧情树与存档

开始界面的两处“继续旧存档”均打开剧情树。切换“一周目”和“非一周目”只浏览对应节点，不更改当前进度；选择已解锁节点或“从上次位置继续”后，才恢复剧情。

## 节点与解锁

- 一周目：序章 → 四幕各自的入场对白、小游戏与剧本对白 → 第四幕结局演出并返回标题。
- 非一周目：四幕各自的入场对白、小游戏与剧本对白 → 最后的存档 → NE、TE、BE 三个独立结局分支。每条分支播放三段剧本并进入对应结尾字幕，然后返回标题。
- 每条主剧情对白分别记录位置，显示这条对白时解锁。小游戏启动、幕间/终幕进入、结局实际播放时解锁对应节点。
- 两棵树独立记录节点；开始非一周目不会自动解锁其后面的章节。未经过的结局保持锁定。
- UI 禁用未解锁节点，`GameManager.restoreStoryNode` 也校验树、节点定义和存档位置，拒绝无记录或错配的节点。

## 回访和恢复

`storyTrees[1|2]` 保存节点快照和该树的 `lastNodeId`，沿用 `zlyc_save_v1` 存储键。快照包含周目、章节、场景、对白位置、当时的剧情标记和小游戏存档，不包含剧情树自身。

回访节点保留所有已经解锁的节点、全局结局记录和当前音量设置；剧情标记及小游戏进度则恢复到那个节点，避免后续选择污染早期剧情。再次走到同一节点时更新其快照。游戏进行中会更新当前小游戏节点的检查点。对白节点记录进入该行时的状态，所以回访选择对白可以重新作答。

第一幕与第二幕沿用原来的重新开始机制；第三幕与第四幕沿用各自细化的检查点存档。新游戏或清除本地存档清空两棵树。

## 旧存档

首次加载旧存档，保留当前节点的准确对白位置、标记和小游戏存档。根据原有顺序重建已走过的必经节点，未来节点继续锁定；非一周目旧存档同时重建已完成的一周目树。旧存档未保存早期节点的历史状态，回访这些重建节点会从对应段落重新开始；未记录的结局不会被开放。

树的节点直接来自 `public/data/scenes.json` 和 `public/data/story.json`。对白节点 ID 使用场景、文本区段键和行号；有现存存档时请避免随意删除或重排行，否则对应节点无法再与原位置匹配。

`tests/story-tree.test.js` 覆盖节点权限、周目隔离、对白与标记恢复、小游戏检查点、结局分支、旧存档迁移和清除行为。

第三幕青年《出门之前》的非一周目另有成功与保留迟到结果两条尾声分支，第四幕在两者之后汇合。仅游玩到的结果会解锁。旧第三幕节点经内容版本迁移后，只保留新入场节点，具体规则见 `BEFORE_DEPARTURE.md`。
