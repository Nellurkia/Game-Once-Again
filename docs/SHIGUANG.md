# 第四幕替换：拾光 v0.2

来源：用户提供的 `拾光_小游戏完整项目_v0.2.zip`。保留其像素场景、横向及纵向探索、场景切片、自动拾取、车站信号谜题、钥匙、出口、安全点、地图和存档导入导出。原包说明及验收记录仅作为参考，本仓库的验证见下文。

## 周目规则

由总游戏传入，一周目映射 `first`，非第一周目映射 `second`，小游戏不自行解锁或切换总游戏周目。

| 配置 | 可取得及必须拼合 | 通关后的画面 |
| --- | --- | --- |
| 一周目 | 11 块通路拼图，加信号谜题和出口钥匙 | 保留相框、车票、合照三处残缺，允许继续剧情 |
| 二周目 | 全部 14 块必须处于 `placed`，加信号谜题和出口钥匙 | 完整记忆；仅拾取到右栏不算完成 |

沿用压缩包的三段地图：旧书房与阁楼、钟楼下的小车站、回廊尽头的灯室。当前两周目使用相同基础地图，二周目开放三枚额外拼图并要求回访，不宣称已经完成两套独立地图设计。

## 集成

- `public/minigames/shiguang/`：来自压缩包的页面、样式、脚本和背景素材。地图在 `level-data.js`，参数在 `config.js`。
- `src/minigames/shiguang/index.js`：同源 iframe 隔离原项目全局样式/事件；通过原有 `MemoryPuzzle.start()` 接入周目、保存适配器和返回总游戏回调。
- 保持 1280×720 无外框舞台，顶部留出总游戏导航空间。打开宿主设置会停止小游戏模拟。
- 通关先显示本关结果，玩家点击“继续故事”才通知宿主进入第四幕尾声。重复进入已完成存档仍可继续，不会被困在本关标题。
- 保存成功必须由宿主确认。存储失败显示未保存，并在后续操作时重试。无效传入快照会阻止自动覆盖；玩家确认重置当前周目后才能重新保存。

## 存档兼容

新版使用总存档 `minigameSaves['shiguang:1']` / `['shiguang:2']`，与旧版的 `memoryPuzzle:1/2` 隔离。旧快照保留，但地图和碎片标识不同，不自动转换。已有章节对话存档继续保留原对话位置；进入新版游戏时按新版记录继续或从起点开始。

旧实现及其测试保留作历史回归参考，第四幕已不再调用。`npm run build` 生成的网站和 `dist/memory-puzzle-offline.html` 都使用新的《拾光》。离线文件内嵌全部脚本、样式和图片，独立默认一周目；总游戏中的二周目通过宿主传入。

自动测试验证 11/14 集合、三处残缺、依赖与章节路由，整套 22 项通过。浏览器验证实际自动拾取、错误/正确拖放、缩放后的拖放、返回再进入恢复、首周目缺块开门、二周目缺块/仅拾取拒绝开门、全拼开门及主剧情回调。通关判定测试使用构造的合法进度与出口位置，不视为重新人工跑完原包的整张地图。
